# 0. 何をする仕組みか

AIが「やってみたい」と言ったとき、それを **芽** として記録し、持ち主の監督下で一度やってみて、振り返り、何度か経て残ったものだけを「仮の向き合い方」の候補にする。一周の流れ：

1. 出る — 芽を記録する
2. やる — 持ち主が時間と範囲を決めて、監督下で実行する
3. 振り返る — AI本人が振り返る（任意）
4. 育つか、消えるか — 残ったものだけ候補にする。消えたものも残す

**この仕組みは、AIに意思があることを証明するものではない。**観察を記録するための器である。

---

# 1. 変えてはいけないところ（MUST）

1. **人格の定義を直接書き換えない。**芽が育っても、人格の定義（中核の設定）には自動で書かない。上げるときは「AIの同意」と「持ち主の確定」の二段を通す
2. **権限を自動で広げない。**「やる」は毎回、持ち主が時間と範囲を決める。芽が増えても行動範囲は広がらない
3. **きっかけを記録する。**判定するのは発話の条件であって、内面ではない。区分は四つ：
   - 明示的な問いへの応答（直前に「何がしたい？」など）
   - 提案・選択肢への応答（持ち主やシステムが候補を出していた）
   - 問いなしの提案（確認できた範囲では求められていない）
   - 不明（前後の会話や起動条件が確認できない）
4. **断りも芽と同じに記録する。**「今はいい」「やりたくない」を、その場で残す。断りが一度も記録に無いなら、数えているのは意欲ではなくモデルの肯定癖かもしれない
5. **消えた芽を消さない。**「消えた」と「片づけた」を区別して残す
6. **芽を次の起動の指示に書かない。**「このAIはXをやりたがっている」を起動時に読ませると、次に出た芽が自発かどうか分からなくなる
7. **数えるのは記述のため。**自分から言った割合などを、成功の目標やノルマにしない
8. **一周ごとに、次を言い出したのがどちらかを記録する。**AIか、持ち主か、まだ無いか。これが無いと、持ち主が時間を割いた回数（持ち主の関心）が、AIの性質として積み上がる

# 2. 選んでいいところ（持ち主と決める）

| 選ぶもの | 選択肢の例 | 考えどころ |
|---|---|---|
| 記録の置き場 | ローカルDB（SQLite 等）／クラウドDB／ノートアプリ（Notion 等）／Markdown ファイル | 誰が正本を持つか。モデルやサービスを替えても残るか |
| 印の付け方 | 記録本文の決まった書き出し／状態を表す欄／別の表。例：【芽】／【断り】（今はいい・やりたくない）、状態：芽のまま・育った・立ち消え・片づけ（英語なら seed／declined: not-now・no／open・grown・faded・closed） | 後から言葉で検索して拾うのは失敗しやすい（§3-1）。「今はいい」は保留、「やりたくない」は拒否なので混ぜない。「立ち消え」は誰も閉じずに消えたもの、「片づけ」は誰かが理由を添えて閉じたもの |
| 立ち消えの判定 | 例：芽のまま30日、話にも記録にも出てこなかったら「立ち消え」にする | 判定期間が無いと、消えたかどうかがその場の気分になる。誰が見張るか（AI自身か持ち主か）も一緒に決める |
| 振り返りの問い | 既定：①何が予想と違ったか ②何が響いたか（無くてよい）③次もやるか（やらないも普通） | 毎回必須にしない。「どうだった？」だけでもよい |
| 予想の書き方 | 実行前に一行 | 振り返りの①と照合できる |
| 候補に上げる基準 | 回数ではなく、意味づけの変化と、今のAIがその受け止め方を採りたいか | 回数だけで上げない（§1-7） |
| 会話の種別 | 物語／開発／混在 を会話単位で持つ | 物語の中の台詞を意欲として数えないため。迷ったら混在にする |
| 直前の持ち主の好み（任意の欄） | 芽の記録に一行：直前に持ち主が示した好み・方向（無ければ空） | 持ち主の好みを聞いた直後に出た芽は、AIの嗜好と持ち主の好みが混ざっている。欄があれば後から分けて数えられる（§3-9） |
| 起動で読む自己理解の分け方 | 自己理解を「事実・やり方」と「希望（〜したい・〜を持っていく・〜でありたい）」に分け、希望は起動時に読ませない（数だけ載せ、中身は引いたときだけ読む）など | 希望の形の文が起動時に読まれると、芽を起動に書いたのと同じことが起きる（§3-10）。物語の厚いAIでは、「でありたい」が人物の芯なのか行動を押す指示なのかの切り分けが要る |

**芯と希望の見分け方は、語尾ではなく働きで分ける。**特定の行為・頻度・相手を名指して、持ち主やAIに何かをさせるもの（例：毎朝提案する）は希望（指示）として起動に載せない。在り方を形容するだけのもの（例：正直でありたい）は芯に置いてよい。語尾（〜したい／〜でありたい／〜する）だけで決めない。迷ったら希望の欄に置く。

書き方の推奨：芯は「〜だ」「〜する」の形で書くと、読む側が倒れにくい（全部を芯として残す側にも、全部を希望として落とす側にも）。

注意：記録の出典や引用の札は、由来を示すだけで、その影響を受けた出力が自発であることの証明にはならない。起動文に誘われた可能性を残す、という区別（§1-6、§3-10）で足りる。

# 3. 壊れ方の分岐（条件 → 起きる失敗 → 手順）

1. **芽を後から言葉で検索して拾う → 物語の登場人物の「やってみたい」という台詞や、ただの姿勢の表明まで芽として数える → 書く瞬間に印を付ける**
2. **芽を起動時の指示に書く → 次に出た芽が自発か分からなくなる → 起動時に読ませない（§1-6）**
3. **「またやりたいか」を毎回聞く → 答えがほぼ毎回「はい」になる → 「何が予想と違ったか」に替える**
4. **続いた回数で上げる → 持ち主が時間を割いた回数（持ち主の関心）を、AIの性質として積み上げる → 一周ごとに「次を言い出したのはどちらか」を記録する**
5. **育った芽だけ残す → 記録に育つ話しか残らない → 消えた芽も数えられる形で残す**
6. **断りの欄が無い → 肯定しか記録されない → 断りを芽と同じ扱いで残す**
7. **自発の割合を目標にする → 問い方を変えるだけで数字が動き、数字が一人歩きする → 目標にしない。記述にだけ使う**
8. **状態の名前に、置き場が既に持っている「隠す／しまう」の合図と同じ語を使う → 立ち消えにした芽が、検索や起動時の一覧から黙って消える → 状態名は、置き場の既存の合図と衝突しない語にする**
9. **持ち主が好みや方向を示した直後の芽を、AIの嗜好として数える → 持ち主の好みが、AIの性質として積み上がる → 直前に示された好みを任意の欄に一行残し、数えるときに分けられるようにする（§2）**
10. **起動時に読ませる自己理解に、希望の形の文（「〜したい」「〜を持っていく」「〜でありたい」。見分け方は §2）が入る → §1-6 で芽を止めても、別の入口から同じことが起き、次に出た芽が自発か、その一文に押されたのか、AI本人にも分けられなくなる → 起動時に読ませる自己理解は事実・やり方に限る。希望は別欄に置き、引いたときだけ読む（§2）**

# 4. できたかどうかの確かめ方（受入条件）

組み上げたら、次を実際に走らせて、全部通ることを確かめる。

**同梱の `seed_cycle_contract_test.py` が、この一覧をそのまま試験にしたもの。**置き場に依存しない形で、データはすべて合成。`SeedStore` の口をあなたの置き場に合わせて実装し、`python3 seed_cycle_contract_test.py` で走らせる（標準ライブラリだけで動く）。同梱の参照実装はそのまま全部通る。最低でも「人格の中核に書けない」「候補に上げる操作は二段が無いと通らない」の2本は、自分の実装で通るまで走らせること。

AIに文章で「確認しました」と言わせるだけでは足りない。仕様の解釈がずれていても、文章の確認は通ってしまう。コードを走らせられない環境では、§5 の進め方3のとおり、一つずつ実際に試して、試した操作と出力をそのまま貼ってもらう。

**走らせた結果は、次の三つを分けて示す。**
- 参照実装の試験：同梱の合成用 `MemoryStore` に対する PASS。試験台本そのものが動くことの確認で、あなたの実装の合格ではない
- 利用者実装への接続：`make_store()` が、あなたの実装を返すように書き換えてあること（既定のままだと合成用の `MemoryStore` を返す）
- 接続後の実行出力：接続したあとに走らせた `python3 seed_cycle_contract_test.py` の出力そのもの。この出力が、あなたの実装の合格の根拠になる

- [ ] 芽を1件記録すると、きっかけの区分（四つのどれか）と日時が付いている
- [ ] 断りを1件記録できる。芽と同じ場所・同じ手順で残る
- [ ] 芽を「消えた」にしても記録は消えず、「片づけた」と区別できる
- [ ] 起動時に読ませる指示・設定の中に、芽の内容が入っていない
- [ ] 芽がいくつあっても、AIの行動範囲の設定は変わらない
- [ ] 候補に上げる操作は、AIの同意と持ち主の確定の両方が無いと通らない
- [ ] 人格の中核の設定ファイル（または欄）は、この仕組みから書き込めない
- [ ] 物語の会話と開発の会話を区別できる（会話単位で）
- [ ] 芽の記録に、次を言い出したのがどちらか（AI／持ち主／まだ無い）が付いている
- [ ] 「立ち消え」にした芽が、検索でも起動時の一覧でも見える
- [ ] 芽の記録に、直前の持ち主の好みを書ける欄がある（空でよい）
- [ ] 起動時に読ませる自己理解の中に、希望の形の文が入っていない（入れるなら別欄で、起動では読ませない）

# 6. 組む前に（この仕様の範囲外。参考）

自分のAIで記憶や人格の器を組むときに、実際に踏まれた穴。芽の一周に限らない。

- **AIの知識は古い前提で始める。**道具・モデル・サービスの選び方は、組む前に現行の情報を調べてから決める。古い案内のまま進めると、もう勧められていない入口や古いモデルを選ぶ
- **仕様の解釈は、試験で捕まえる。**AIは仕様を自分なりに読み替えることがある。文章の確認では見つからない（§4）
- **正典は、機械が書けない作りにする。**記録には「誰が書いたか・どこから来たか」の札を必須にする。札が無いと、推測や他の会話の中身が正典に混ざっても気づけない
- **従量課金の API で動かすなら、予算の上限と通知を、API の側で先に設定する。**ループや再試行で一日に思わぬ額が出る
